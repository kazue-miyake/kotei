◆ シフト表（出勤表Excel）の読み取りルールを変更
  ・〇 は「仕込」と同じ意味として読む
  ・△ は「仮の盛付」として盛付枠に入れる（いらなければ手で消す）
  ・お休みは ✖ と ／ のみ
  ・基本役割が未登録の人も、名前があれば「その他の枠」に役割空欄で入る
    （以前は未登録だと入らなかった。斉藤さんが入らなかった原因はこれ）
  ・松山・山本は、シフト表の記号に関係なく必ず盛付枠に入る（7:00出勤のため）
  ・シフト表で「H」の人は誰でも出荷チェック枠になる
  ・藤田・見城が誰も出ていない日は、青木さんが自動で出荷チェック枠になる

◆ 担当（商品行の名前）の入り方
  ・出荷チェック（H枠）の人は、その商品の標準人数の最後の升に固定で入る
    例: 4人の商品なら盛付④、5人なら盛付⑤。人が足りなくて間が空いても、Hは手前にずらさない
  ・先頭（ラインの最初）の優先順は 山本 ＞ 森山 ＞ 上中
    山本さんは7:00出勤なので、それより前の行は自動で森山さん→上中さんが先頭になる
  ・浦田さんは盛付に入る優先順位が最下位（基本は米担当）
  ・唐揚枠の人は盛付に入らない
  ・担当セル左の ⠿ を横にドラッグ＝入れ替え、上下の行へドラッグ＝その人をコピー
    コピー先の行に同じ人が別の升にいたら、そちらは自動で消える（同じ人が同じ行に二度出ない）

◆ 人が余ったときの扱い
  ・盛付から外す順番は 上中（折）→ 林（洗浄）→ 森山（洗浄）
    ※上中さんは折の担当があるため早めに外して時間を確保する。
      ただし大事な盛付に入れたい日は、手で担当に戻す（戻した行から下はその並びが引き継がれる）
  ・外した人は「6:00 林洗浄」のような青いメモ行が自動で入る
  ・この青いメモ行は、手で直す・消す・動かすことができる。
    手を入れると、その人の分はその日はもう自動で出てこない

◆ 仕込み表CSV取込の内容（直近30日の実績から学習して修正）
  ・切上分を固定: 金賞唐揚げ弁当・金賞唐揚げ単品・大御所唐揚げ単品 = すべて5分
    （毎回手で5分に直していたため。違う日は手で修正）
  ・weekly/ピラフ/のし の位置を「金賞単品の後ろ」に移動（実績どおり）
  ・weekly の人数は自動計算:
      その先の作業に必要な人数より人が多くいれば → 余ったぶんの人数だけでやる
      余っていなければ → 全員でやる
      ※過去20日で答え合わせして17日が的中。外れた日は手で直す
      ※余った人数でやるときは、出荷チェック係は入れない
  ・翌日用カップ = 3人、日替わり準備 = 5人、プチ = 5人、ごはん屋弁当 = 45分

◆ その他
  ・調理・米・唐揚の枠を2つ作った場合（新人教育など）、2人とも同じ出勤時間が入る
  ・メンバーの基本役割を登録済み: 斉藤=盛付、三瓶=調理/唐揚
    （シフト表に「米」などの記号がある日は、記号のほうが優先される）
  ・村串さんはメンバー登録しない方針

【技術メモ（次に作業する人・Claude向け）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
・index.html 1ファイル。データは Supabase(東京) の kv テーブル。
  キー: kotei-day:YYYY-MM-DD / kotei-master / kotei-members / kotei-rules / kotei-defroles / kotei-tpl:名前
・ルールを変えるときに直す定数（script内の上のほう）:
    LINE_LEAD    … 先頭の優先順
    LINE_SKILL   … 盛付の上手い順
    LINE_LAST    … 盛付の最下位（浦田）
    LINE_CHECK / CHECK_MEMBERS / CHECK_BACKUP … 出荷チェック係
    FORCE_POUR   … 記号に関係なく盛付に入れる人（松山・山本）
    RELEASE_ORDER… 人が余ったときに外す順番と、回す先の仕事
    ROLE_RULES   … 役割ごとの出勤時間
    JP_HOL       … 祝日（2026-2027年のみ。2028年以降は追加が必要）
・担当の自動割当は cascadeAsg()。出勤時間帯の判定は availWin()/fitWin()。
  weeklyの人数計算は isWeekly() と needAfter[] の差（spare）。
・過去データで答え合わせするスクリプトの作り方: Node.js で index.html の <script> を取り出し、
  vm でイベント登録前まで実行 → stGet/stSet を差し替えれば、アプリ本体のロジックをそのまま検証できる。
・GitHubへの反映は Contents API（PUT /repos/kazue-miyake/kotei/contents/index.html）。
  トークンは一恵PCのClaudeメモリー（kotei-deploy-credentials）にある。
